# CacheMap versus F# Map: full results

[Design, findings, and limitations](cache-map.md). These are isolated process timings, managed allocations, and GC statistics; CPU cache misses were not measured.

Primary run: two warmups, five measured iterations targeting 100 ms. String read confirmation: five warmups, twelve measured iterations targeting 200 ms. Both use one launch, Release, BenchmarkDotNet 0.15.8, .NET SDK 10.0.401 / runtime 10.0.13, Windows 11. CPU identity and power-plan control were unavailable. Error is half the 99.9% confidence interval.

Both original and confirmation measurements are preserved. The findings use the longer confirmation for string reads.

Source provenance: measured CacheMap SHA-256 `fab07fa76a936aa9b281749e326c6748a0c18cb852816fc9bb1dd9692a4fd3c3`; validated final source `86900fe755c6247c84b107cb8a398bd7fc3d63550af5e93caeb311cc5833fc4a`. After measurement, only the unbenchmarked partition function and its callback-order comment changed to match F# Map. All timed operation implementations are unchanged. Final source passed 93 tests and benchmark output validation.
